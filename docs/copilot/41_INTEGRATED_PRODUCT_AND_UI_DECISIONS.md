# 41 — Integrated product and UI decisions (design-approved; machine contracts separately gated)

**Status / authority:** This document integrates the product decisions from the WRLD Video Studio design discussion into the existing four-screen UI specification. It is authoritative for **intended UX direction**, not for exact API paths, JSON schema fields, FFmpeg algorithms, feature completion, or approval to implement a work unit. Docs 31–40 and existing implemented contracts remain authoritative for their respective generations, work-unit boundaries, and acceptance gates. If a design conflicts with an existing technical contract, report the conflict and propose an additive, separately approved contract; never silently modify historical generations.

## Product interaction model

- Preserve four main navigation destinations **Import → Review → Metadata → Render** from Docs 16–17 and `docs/ui/index.html`; do not replace the prototype or treat it as production code. Composition is a panel/workspace within Review initially; a dedicated advanced composition editor is a future WU7 concern. A Project Library selector may appear within Import or as a shell-level entry point, not necessarily a fifth mandatory page.
- One album or track is **active for editing** at a time. Multi-select album/track rows in a library or queue can request bulk validation, metadata operations, and rendering later. Batch selection must deduplicate album/track overlap and show a confirmation/impact preview. Initial render concurrency remains one worker, using the existing lifecycle; do not create a second scheduler.
- Use **inline controls** for frequent camera, waveform, color, visualizer and timing edits. Use **focused dialogs** for asset selection, reset, presets, and similar tasks; use **multi-step wizards** for album import, assembling multiple visual clips, batch configuration, and export preparation. Large waveform/video editing requires a roomy or full-screen dialog. No nested configuration dialogs. Back retains wizard draft state; Cancel is non-destructive; final confirmation validates before persisting.
- Automatic, genre-specific starting preset for newly imported/created albums. Hierarchy: **global defaults → genre preset → album defaults → optional track overrides → optional Short overrides**. Show effective value and source, allow Reset to Inherited, and never silently overwrite manual changes on preset updates. Genre examples are creative suggestions, **not approved numeric parameters or mandatory palette algorithms**. Exact preset schema, default mappings, and migration policy require a later contract gate.
- Create **one primary Short draft per manifest-backed track** using the Phase 0/Phase 1 approved deterministic rule: start at normalized sample zero; default to 30 seconds; use the whole track when shorter; tracks shorter than five seconds require review and cannot be approved. Preserve the stable backend-owned identity and manual edits. Optional analyzer suggestions are separately sourced candidates and never fabricate approval or replace the deterministic fallback silently. Additional Shorts remain future work.
- Short visuals inherit album defaults with optional mood-informed, non-destructive treatment. Any mood/energy input must be sourced, typed and provenance-aware; don't fabricate values. Short and track may replace artwork/visual source with imported trusted project resources. Never overwrite original WAV, image, video, canonical album manifest, or analyzer output.
- Draft saving and approval are distinct: future design intent is **autosaved drafts** (not WU4 baseline), manual approval for Shorts and publishing metadata, undo/redo and restorable meaningful configuration versions. Existing WU4 explicit Save, dirty state and revision conflict behavior (Docs 15–16) remains in force **until** a separate autosave/conflict/undo contract is approved. Autosave must not suppress 409 conflicts, silently rebase approved work, or overwrite stale manifests.
- Instant composition preview updates reactively and is **explicitly approximate** where necessary; authoritative rendered preview uses the existing FFmpeg production path, with bounded selectable excerpts and private lease ownership. Never describe a browser approximation as verified production output. The renderer remains the single authority.

## Import and project library

- Import uses one standard trusted-project path. The user selects a directory beneath a configured trusted root; the application assigns a stable opaque project identity and recursively inventories supported assets without requiring a manifest, fixed subdirectories, audio or artwork. No arbitrary browser-provided server paths or hardcoded library roots are accepted.
- Discovery is bounded, cancellable and security-preserving. It reports project-relative assets, counts, capability status and per-file diagnostics. It does not assign creative roles, infer album/track identity from filenames, judge aesthetic suitability, or reject an otherwise safe project because artwork is absent.
- A recognized manifest enriches the project with stable album/track identities, ordering and approved renderer settings. It does not create a second user-facing ingestion mode and must never be rewritten automatically. Existing manifest-backed projects retain their project IDs and stored editor relationships through a separately approved migration.
- Production workflow selection and composition follow registration. The user selects included tracks/order and background type in downstream Review/composition. Shared media browsers may audition or inspect assets where capability contracts permit. A discovered asset is not necessarily browser-playable or renderable.
- Genre presets remain unavailable until their resolver/preset contract is approved. Publishing-metadata generation belongs to WU5. Reimport/rescan preserves user edits and marks missing or changed referenced assets without deleting source data.

## Review and composition

- Keep WaveSurfer Regions, keyboard/numeric time entry, selection-limited playback, stable Short IDs, WU3 Original/Split/Treated comparison, bounded WU3B effects and authoritative motion preview. The primary Short and alternative suggestion UX is layered over those contracts.
- Background type is selected in Review/composition, not during Import. A solid-color background needs no imported artwork, but remains draft-only until an additive authoritative renderer generation supports it. Static image selection uses approved project asset references. Layered/parallax and procedural backgrounds remain future capabilities.
- Extend the visual-source concept **in a future approved renderer generation**: still image; imported MP4; or ordered playlist of images/MP4s. MP4 may be an independently looping background or a longer synchronized album video; track and Short can choose independent visual time windows. Imported video audio is normally excluded from final music exports. All imported media must be snapshotted or safely referenced through the trusted project resource boundary.
- Visual effects are independently toggleable. Imported MP4 is **not** forbidden from pan/zoom, color grade, visualizer, progress, or overlay treatment merely because footage already moves. Use conservative defaults and non-blocking aesthetic warnings; only technical validity/security/incompatibility can block.
- Video timing modes: **fit to target duration** (speed up/slow down), loop, trim, freeze final frame, custom speed/remaining-time behavior. Fit speed = source duration / target duration; e.g., 150 seconds of video over 180 seconds of music plays at 83.33% speed. Standard frame duplication/drop and optional optical-flow interpolation are *future options*, not guaranteed renderer capabilities. Clearly warn for extreme ratios without arbitrary creative hard limits. Video and music timelines remain independently defined; no WAV tempo/pitch changes.
- Ordered clip playlist is the first composition model, **not** a full nonlinear editor. Allow default transition per playlist with optional per-boundary override: cut, crossfade, fade-to-black. Transition duration is configurable and must participate in validated timeline calculations. More elaborate multi-layer timeline and keyframing are deferred.
- A visual-source wizard may use **Source → Timing → Effects → Review** steps. Actual clip-list and file-picker affordances should be designed around project-scoped resource registration; the wizard is not permission to accept arbitrary local paths as trusted backend resources.

## Metadata

- Retain Docs 19, 23, 24, 26: Table/Detail, deterministic generation, supplied/generated/edited/approved provenance, validation, batch editing, chapter consistency and output export. Auto-generate drafts on import **when the WU5 capability exists**, otherwise queue/mark pending; do not claim WU4 implements WU5.
- Approve per item or in bulk after review. Manual edits and approved content are never silently replaced by regeneration. Metadata approval and Short approval are separate statuses; neither triggers rendering. Publishing/upload automation is future scope.

## Render

- Retain Doc 30 progress and the existing WU2/WU3A/WU3B immutable jobs, admission, cancellation, recovery, output verification and artifact identity. Plan individual track, Short and album exports, multi-selection batch jobs, 16:9 YouTube and 9:16 Shorts profiles, preflight/confirmation, retry/reorder/pause-between-jobs, progress/history and artifact links. Actual support for Shorts/profile variants and multi-album orchestration remains subject to future work-unit contracts.
- **Incremental rendering:** reuse only a previously **verified** artifact when source fingerprints, manifest generation, resolved configuration, renderer/profile identity, timeline and relevant dependencies match. No silent overwrite, no reuse based on filename or timestamps alone. Existing WU3A/WU3B reuse/namespace policies remain authoritative; design new incremental behavior additively.
- Export approval is not automatic publication. YouTube upload and other distribution remain separate future workflows.

## Accessibility and acceptance intent

- Keyboard/touch-accessible region and clip controls; modal focus management and Escape/Cancel semantics; accessible step labels and error summaries; no color-only status; confirmation for bulk/destructive actions.
- Test inheritance and reset, genre-preset initialization, primary Short suggestions/fallbacks, alternative range replacement, draft/approval separation, stale revision conflict, modal cancel/back, independent video timing, playlist transitions, instant-versus-rendered preview labeling, verified-only incremental reuse and source boundary containment when the corresponding feature is implemented.

## Review reconciliation (Codex independent assessment, 2026-10-29)

- **WU4 baseline uses explicit Save**, dirty-state feedback, optimistic revision conflicts and local unsaved undo/redo. Server autosave and durable configuration history are separate future contracts; approval is never autosaved.
- A **backend-owned typed resolver** should eventually report effective setting, source level, explicit override flag, and preset/version provenance. Reset to Inherited deletes the override; it does not copy a parent value. Exact preset mappings are unapproved.
- One primary Short per manifest-backed track remains the approved baseline. Phase 1 implements the approved stable identity, deterministic fallback, short-track review rule and approval invalidation candidate; verify source/tests before claiming acceptance. Alternative analyzer suggestions remain unimplemented and separately gated.
- MP4 imports, clip playlists, speed fit, transitions and video frame interpolation are **not implemented** and are allocated to a separately gated WU8. Optical-flow interpolation is deferred.
- Do not imply WU4 provides Metadata or Render workflows. The four-route shell may mark them explicitly unavailable until WU5/WU6.
- The images under `docs/ui/` are **legacy reference screenshots**, not up-to-date acceptance criteria: they include a three-entry navigation, two default Shorts and unimplemented render outputs.
